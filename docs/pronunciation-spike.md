# FRA-132 browser pronunciation feasibility

Open `/pronunciation-spike` while signed in on the PR preview. The route is deliberately absent from navigation and never uploads audio. It is a **feasibility test**, not learner feedback: decoded phonemes alone are not a pronunciation grade.

The worker pins `qnighy/wav2vec2-xlsr-53-espeak-cv-ft-ONNX` at revision `d2987af7ae07d53eafee15dc7190479062faa1e8`, downloads its q4 model (241 MB), and uses Transformers.js on WASM. Recording decoding and resampling produce 16 kHz mono PCM. The worker runs greedy CTC decoding (argmax, collapse repeats, then remove blank) and reports model load and inference times. The model and metadata may be cached by the browser; Safari may evict them. The current Read Aloud path and Groq fallback are untouched.

## Required device test before integration

1. On Samyak's iPhone in Safari, use Wi-Fi and open the PR preview's `/pronunciation-spike` route. Check the download box and analyze a 3-second French recording. Record cold load time, inference time, and whether Safari stays responsive. Reload and repeat to verify the model cache.
2. Repeat with 1-second and 5-second clips. Use Safari Web Inspector or Instruments from a Mac to measure peak memory; browser JavaScript cannot reliably report Safari's process memory. The ticket's gates are about 8 seconds for a 3-second clip and about 400 MB peak memory.
3. Run the twelve clips from the original spike report, including `ouais_en`, `merci_bad`, and `bonjour_bad`. Compare detected phone substitutions against the Python reference. The report and clips were not available in this workspace, so this parity check remains open.
4. Repeat one 3-second clip in desktop Chrome. Test quiet and very short recordings; the page must show an error rather than phoneme output.

If the iPhone gates fail, stop the browser route and evaluate the server option. If they pass, the next implementation must add offline espeak-ng reference phonemes to content revisions, CTC forced alignment against those references, calibrated per-phone and per-word feedback on real learner audio, and an opt-in download and fallback in the Read Aloud exercise. Recognition output from this spike must not be used as a score. The model's published q4 accuracy comparison used two non-French clips, so it does not validate French learner feedback.

## Phase 2 implementation contract (only after go/no-go)

- **Reference data:** add a versioned `pronunciation_reference` to the content revision for `speaking_prompt` phrases. It contains the exact display words, per-word IPA phones, eSpeak-ng French voice/version, and generation version. Generate this during content import/revision creation with a build-time-only eSpeak-ng tool; verify the word count and refuse invalid references. Backfill published Read Aloud items through the normal reviewed content process. Do not ship eSpeak-ng in the browser bundle or invoke it on Render at request time.
- **Alignment:** pass the reference phones and 16 kHz PCM to the worker. Run CTC forced alignment (Viterbi with blank and repeated-phone transitions) over frame log probabilities; greedy output alone is insufficient to score a specified phrase. For each aligned phone span, compare the reference phone's log probability to the strongest competing phone on the same frames. Aggregate into per-word *signals* without a single overall score. Guard duration, peak/RMS energy, clipping, and truncated endings before alignment. Thresholds must be tuned on real learner audio and explicitly marked provisional.
- **Feedback:** use only supported observations: “The R in ‘merci’ was unclear; try it again.” Name a specific alternate sound only when the decoded competitor and calibrated margin support it. Never infer a different word from a phone score. Show “couldn't hear clearly, try again” when the recording fails the pre-score gate.
- **Read Aloud UX:** lazy-load after the learner chooses on-device checking. Show the size and progress before downloading; make “skip for now” use the existing Groq transcription path. Safari does not reliably expose cellular status, so show the data-use warning on every first download. Cache by pinned revision and allow a fresh download after eviction or revision change. Worker failure, load failure, or timeout must show the fallback choice instead of a dead end.
- **Privacy and completion:** on-device success submits only `{ completed: true }` to the existing attempts endpoint; `validateSpeakingCompletion` already permits that shape. Audio, transcript, phones, and scores stay in worker memory and are discarded on exit. The Groq fallback *does* upload audio; tell learners before taking it. Do not add score analytics in this phase.
- **Validation:** use the twelve reference clips for parity, then a labelled set of real French learner recordings at multiple proficiency levels and microphone conditions. Measure false reassurance and false warnings before setting any “good/shaky” threshold. Test worker crash, cache eviction, slow device, denied microphone, silent/short/truncated audio, and successful save. Keep the model behind a feature flag until this validation passes.
